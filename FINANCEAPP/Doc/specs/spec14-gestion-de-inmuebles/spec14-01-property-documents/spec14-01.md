> Adjuntar recibos y facturas a cada inmueble, borrarlos en cascada con él y, si hay una clave de API de Claude en Configuración, leer con IA la empresa, el importe y la fecha para crear un gasto.

## 1. Contexto y objetivo

Un inmueble solo guarda datos y operaciones (ingresos y gastos); no se puede conservar el recibo o la factura que justifica cada gasto. Esta feature permite adjuntar documentos a cada inmueble y, de forma opcional, pedir a la IA de Claude que lea la factura para rellenar los datos del gasto.

Petición original:

> en gestión de propiedades de inmuebles este la acción de adjuntar documentación y podamos subir recibos y facturas que estan vinculadas a cada propiedad y que se propaga el borrado de estos si eliminamos la propiedad, en configuración añadiremos un campo para añadir la api key de claude […] importante que aunque no vaya el ocr me tiene que dejar subir documentación simplememte que no rellenará los campos de forma automática

Comprobado en el código y en la documentación de Anthropic: `Property` no tiene documentos y `DeletePropertyAsync` solo borra las operaciones (enlazadas por nombre); `PropertyOperation.Type` admite Alquiler, Venta, Comunidad, IBI, Hipoteca, Reforma, Seguro y Servicios; `AppSettings` guarda texto y binarios; el logo se sube con `InputFile` en Configuración. Anthropic no permite iniciar sesión con una cuenta de Claude en aplicaciones de terceros ni usar su suscripción: las aplicaciones deben usar una clave de API de la consola (SPEC-14-01 usa esa clave, que el usuario escribe y es suya, y el uso se factura a ella). La API de Mensajes acepta imágenes (JPEG, PNG, GIF, WebP) y PDF en base64; el modelo más barato con visión de la lista actual es `claude-haiku-4-5-20251001`.

## 2. Usuarios

Un único usuario: el propietario de la aplicación, que gestiona sus inmuebles en Windows, Android o iOS.

## 3. Historias de usuario

- Como propietario, quiero adjuntar recibos y facturas a un inmueble, para tenerlos juntos y localizados.
- Como propietario, quiero que al borrar un inmueble se borren sus documentos, para no dejar archivos huérfanos.
- Como propietario, quiero guardar mi clave de API de Claude en Configuración, para activar la lectura con IA.
- Como propietario, quiero que la IA lea la empresa, el importe y la fecha de una factura, para no teclearlos.
- Como propietario, quiero crear el gasto del inmueble desde el documento, para registrarlo sin copiar los datos.
- Como propietario, quiero poder adjuntar documentos aunque no tenga clave, para no depender de la IA.

## 4. Requisitos funcionales

### RF-1 · Esquema
Nueva tabla `PropertyDocuments`, creada solo desde `DatabaseSchemaUpgrader`.
- [ ] La tabla guarda `Id`, `PropertyId`, `FileName`, `ContentType`, `SizeBytes`, `Content`, `Description`, `UploadedAt`, `ExtractedCompany`, `ExtractedAmount`, `ExtractedDate`, `ExtractedType`, `AiReadAt` y `PropertyOperationId`.
- [ ] Arrancar con una base anterior no pierde datos y deja la tabla vacía.
- [ ] Arrancar dos veces seguidas no cambia nada.

### RF-2 · Adjuntar documentos
En el detalle de cada inmueble de `/inmuebles` hay una sección «Documentación».
- [ ] Se puede adjuntar un archivo de cualquier tipo salvo los bloqueados, sin clave de API y sin conexión.
- [ ] Se rechazan con un mensaje los archivos ejecutables o de script (.exe, .bat, .cmd, .com, .msi, .ps1, .vbs, .vbe, .js, .jse, .wsf, .scr, .lnk, .jar, .reg, .dll), sin distinguir mayúsculas.
- [ ] El archivo se guarda en la base de datos con su nombre, tipo y tamaño.
- [ ] Se rechaza un archivo vacío o de más de 10 MB con un mensaje en español.
- [ ] Se puede añadir una descripción opcional (hasta 200 caracteres).
- [ ] Se pueden adjuntar varios documentos a un mismo inmueble y repetir nombres.
- [ ] Un inmueble vendido también admite documentos.
- [ ] Funciona en Windows, Android e iOS con el selector de archivos del sistema.

### RF-3 · Consultar, abrir y eliminar
- [ ] La sección lista nombre, descripción, tamaño, fecha de subida y estado de la lectura (sin leer, leído o gasto creado).
- [ ] «Abrir» abre el archivo con la aplicación del sistema (imagen, PDF, etc.) usando una copia temporal, que se borra al arrancar la aplicación.
- [ ] «Eliminar» pide confirmación y borra solo ese documento.
- [ ] Eliminar un documento con gasto creado no borra el gasto.
- [ ] La lista de un inmueble sin documentos lo indica.

### RF-4 · Borrado en cascada
- [ ] Al eliminar un inmueble se eliminan también todos sus documentos, en la misma transacción que sus operaciones.
- [ ] La ventana de confirmación indica cuántos documentos se perderán.
- [ ] Si falla el borrado, no se pierde ni el inmueble, ni las operaciones, ni los documentos.
- [ ] Cada inmueble muestra el espacio que ocupan sus documentos.
- [ ] Los documentos se enlazan por `PropertyId`, así que renombrar el inmueble no los desvincula.

### RF-5 · Clave de API de Claude en Configuración
Tarjeta «Lectura de facturas con IA» en `/settings`.
- [ ] Se puede escribir y guardar la clave en un campo oculto; se guarda en el almacén seguro del dispositivo (`SecureStorage`), no en la base de datos ni en los backups.
- [ ] Una vez guardada, la tarjeta muestra «Clave guardada» y sus últimos 4 caracteres, nunca la clave completa.
- [ ] Se puede quitar la clave guardada.
- [ ] Se puede indicar el modelo (texto editable, por defecto `claude-haiku-4-5-20251001`); se guarda en `AppSettings` (`AiModel`).
- [ ] Una clave vacía o con espacios no se guarda.
- [ ] Si el almacén seguro falla, se muestra un mensaje y la clave no se guarda en ningún otro sitio.
- [ ] La tarjeta avisa de que al leer un documento se envía a Anthropic y se factura a esa clave.

### RF-6 · Leer con IA
- [ ] Cada documento imagen (JPEG, PNG, GIF, WebP) o PDF tiene un botón «Leer con IA»; los demás tipos no lo tienen.
- [ ] El botón está deshabilitado y explica por qué si no hay clave guardada; subir y abrir siguen funcionando.
- [ ] Al pulsarlo, el documento se envía a la API de Mensajes de Claude y se rellenan empresa, importe, fecha y tipo de gasto sugerido (uno de la lista de tipos del inmueble).
- [ ] Solo se lee si el archivo es una imagen de hasta 7 MB o un PDF de hasta 10 MB; si no, se avisa.
- [ ] Antes de enviar, una ventana de confirmación avisa de que el documento se enviará a Anthropic y se facturará a la clave; solo si el usuario acepta se envía.
- [ ] Mientras lee, el botón se deshabilita y muestra un indicador, así que no hay doble envío.
- [ ] Si el tipo sugerido no encaja con la lista, queda vacío y lo elige el usuario.
- [ ] Un modelo inexistente da un mensaje específico que indica revisar el nombre en Configuración.
- [ ] Si falla (sin conexión, clave no válida, límite de uso, respuesta no entendida), se muestra un mensaje en español y no se cambia ningún dato.
- [ ] Si el documento no parece una factura, los campos quedan vacíos con un aviso.
- [ ] Releer un documento que ya tiene datos pide confirmación antes de sobrescribirlos.
- [ ] Subir un documento nunca lo envía a la IA.

### RF-7 · Editar los datos del documento
- [ ] Empresa, importe, fecha y tipo sugerido se pueden escribir o corregir a mano, con o sin clave.
- [ ] El importe debe ser mayor que 0 si se informa; la empresa admite hasta 200 caracteres.
- [ ] Los datos se guardan en el documento al pulsar «Guardar».

### RF-8 · Crear gasto desde el documento
- [ ] El botón «Crear gasto» está activo con importe y fecha informados y sin gasto ya creado.
- [ ] Abre una ventana «Crear gasto» dentro del detalle del inmueble con el gasto precargado (categoría Gasto, tipo sugerido, importe, fecha, descripción con la empresa y el nombre del archivo) para que el usuario lo confirme o cambie; nada se crea sin confirmar y el tipo es obligatorio.
- [ ] Al confirmar, se crea el gasto con `CreateOperationAsync`, el inmueble recalcula sus totales y el documento guarda el `PropertyOperationId`.
- [ ] Un documento con gasto creado muestra «Gasto creado» y no permite crear otro.
- [ ] Si se elimina el gasto desde las operaciones, el documento queda libre de nuevo.

### RF-9 · Textos y formato
- [ ] Todos los textos y mensajes son en español.
- [ ] Los tamaños se muestran en KB o MB y las fechas como dd/MM/yyyy.

## 5. Requisitos no funcionales

- **Datos:** los documentos viven en la base de datos y entran en los backups; la base crece con cada adjunto (límite de 10 MB por archivo). La clave de API no entra en la base ni en los backups: al restaurar una copia en otro dispositivo hay que volver a introducirla.
- **Privacidad:** la lectura solo ocurre al pulsar «Leer con IA»; el documento completo se envía a Anthropic. Nunca se escribe la clave en registros ni en mensajes de error.
- **Rendimiento:** la lectura puede tardar varios segundos y falla sin conexión; con timeout y sin bloquear el resto de la pantalla.
- **Compatibilidad:** Windows, Android e iOS; sin paquetes nuevos (HttpClient, `SecureStorage`, `Launcher` y `InputFile` ya forman parte de .NET MAUI y Blazor).
- **Coste:** cada lectura se factura a la clave del usuario; no se muestra el coste.
- **Idioma:** textos en español; código, tablas y rutas en inglés.

## 6. Casos límite

- Clave revocada o sin saldo: error legible en la lectura, subida intacta.
- Almacén seguro no disponible (por ejemplo Windows sin empaquetar): no se puede guardar la clave y se indica; la lectura queda desactivada.
- Imagen muy grande: se avisa y se puede adjuntar sin leer.
- PDF protegido con contraseña: la API puede rechazarlo; se avisa y se conserva.
- Importe leído en otra divisa o con formato raro: se guarda lo que devuelve el modelo y el usuario lo corrige antes de crear el gasto; los inmuebles asumen la divisa base y no hay conversión.
- Abono con importe negativo: solo se admiten importes mayores que 0; el abono se anota a mano.
- Subir un archivo grande: el límite de subida de Blazor (500 KB por defecto) se amplía a 10 MB.
- Extensión bloqueada con mayúsculas o doble extensión (factura.pdf.exe): se bloquea por la última extensión.
- Dos documentos de la misma factura: se permite; el usuario decide.
- Inmueble renombrado: los documentos siguen vinculados (por `PropertyId`).
- Inmueble vendido: conserva sus documentos.
- Restaurar un backup en otro equipo: documentos incluidos, clave no.
- Borrar la clave: los documentos y datos leídos se conservan.

## 7. Fuera de alcance

- OCR local o de plataforma.
- Lectura automática al subir.
- Iniciar sesión con una cuenta de Claude o usar una suscripción (no permitido por Anthropic).
- Documentos de fondos, empresas, cuentas o activos refugio.
- Carpetas, etiquetas, búsqueda, versiones o compartir documentos.
- Probar o validar la clave al guardarla, contador de coste o límite de uso.
- Corregir que renombrar un inmueble deje huérfanas sus operaciones por nombre (comportamiento actual de SPEC-15).
- Editar el contenido del archivo o generar vistas previas incrustadas.

## 9. Decisiones cerradas con el usuario

| Decisión | Resultado |
|---|---|
| Almacén de archivos | Dentro de la base de datos (binario en SQLite) |
| Formatos | Cualquier archivo; la IA solo lee imagen y PDF |
| Sin clave | Subir y consultar siempre funciona; solo la lectura se desactiva |
| Clave de API | `SecureStorage` del dispositivo (no la base de datos) |
| Cuenta de Claude | No viable (Anthropic no lo permite): se usa una clave de API propia del usuario |
| Cuándo se lee | Botón «Leer con IA» en cada documento |
| Resultado de la IA | Se guarda en el documento (editable) y botón «Crear gasto» con confirmación |
| Enlace gasto-documento | El documento recuerda su gasto; al borrar el gasto queda libre |
| Vínculo con el inmueble | Por `PropertyId` (no por nombre) |
| Modelo | Campo editable en Configuración, por defecto `claude-haiku-4-5-20251001` |
| Ejecutables | Se bloquean al adjuntar con una lista cerrada de extensiones |
| Privacidad | Ventana de confirmación antes de cada lectura con IA, además del aviso fijo en Configuración |
| Copias temporales | Se borran al arrancar la aplicación |
| Espacio | Sin tope total; cada inmueble muestra el espacio que ocupan sus documentos |
