# Plan SPEC-02-05 · Filtro por periodo en el histórico de ventas

Spec: [spec02-05.md](spec02-05.md) · Tareas: [task02-05.md](task02-05.md)

## 1. Enfoque

Todo es lectura: sin cambios de esquema, de modelo ni de datos guardados (constitución 5). La lógica va en `Services/` y la página solo pinta (principio 3). Sin paquetes nuevos (principio 1).

1. Un tipo nuevo `SalesPeriodFilter` (en `Services/`) encapsula modo, fecha de referencia, rango, etiqueta y navegación. Añadir un modo es añadir un valor al enum y un caso en tres métodos.
2. `ISaleHistoryService` gana lecturas filtradas.
3. `ExchangeRateService.GetConvertedSaleTotalsAsync` pasa a convertir con los tipos guardados en cada venta y compra cerrada (RF-10), con la misma firma.
4. `SalesHistoryList.razor` añade el selector y llama a los servicios con el filtro.

## 2. Diseño

### 2.1 `SalesPeriodFilter` (`Services/SalesPeriodFilter.cs`)

```
enum SalesPeriodMode { All, Day, Month, Year }      // ampliable: Range, Quarter…

class SalesPeriodFilter
  Mode: SalesPeriodMode
  Reference: DateTime                // día de referencia (solo la fecha)
  static All / ForMode(mode, reference)
  (DateTime? From, DateTime? ToExclusive) GetRange()
  string Label                       // cultura es-ES
  SalesPeriodFilter Previous() / Next()
  SalesPeriodFilter WithMode(mode)   // RF-4: conserva Reference
```

`GetRange()` (rango semiabierto, así una venta con hora entra en su día):
- All → `(null, null)`.
- Day → `[ref.Date, ref.Date+1d)`.
- Month → `[1 del mes, 1 del mes siguiente)`.
- Year → `[1 ene, 1 ene siguiente)`.

`Previous()/Next()`: ±1 día, ±1 mes (`AddMonths`) o ±1 año sobre `Reference` normalizada al inicio del periodo; en All devuelve el mismo filtro (los botones se desactivan en la página). `WithMode`: Reference se queda; desde All usa `DateTime.Today`; Mes → día 1; Año → 1 de enero (RF-4; la normalización va en `ForMode`). El año válido es 2000–2100 (RF-3); `TryCreate` devuelve null fuera de rango, y la página muestra el aviso y conserva el filtro anterior.
Etiquetas: «Total histórico», «dd/MM/yyyy», «Octubre de 2026» (`CultureInfo("es-ES")`, primera letra en mayúscula), «Año 2026».

### 2.2 `ISaleHistoryService` / `SaleHistoryService`

- `Task<List<SaleHistory>> GetByPeriodAsync(SalesPeriodFilter filter)`: `AsNoTracking`, `Where` `SaleDate >= From` y `< ToExclusive` cuando existan, mismo orden que `GetAllAsync` (fecha desc, Id desc). `GetAllAsync` pasa a delegar en All.
- `Task<bool> HasAnyAsync()`: `AnyAsync` sobre `SalesHistory`, para distinguir «sin ventas en la BD» (mensaje actual) de «sin ventas en el periodo» (RF-7).

### 2.3 Conversión con tipos guardados (RF-10) en `ExchangeRateService.GetConvertedSaleTotalsAsync`

Firma intacta: `(IEnumerable<SaleHistory> sales, IReadOnlyDictionary<string,string> currencyByCompany)`; el resultado `ConvertedSaleTotals` gana `ApproximateSales` (ventas que usaron el tipo actual en algún componente) y `ConvertedSales` pasa a significar «convertidas con tipos guardados o aproximados».

Algoritmo:
1. `baseCurrency` y diccionario de tipos actuales (como hoy).
2. Con los ids de los registros: una consulta a `Operations` por `Id IN OperationId` (las Ventas) y otra por `SaleHistoryId IN ids` (compras cerradas), ambas `AsNoTracking`, agrupadas en diccionarios.
3. Por cada registro:
   - Divisa de la empresa = `currencyByCompany` normalizada; si es la base: suma `Amount`, `Commission`, `Profit` guardados (factor 1) y sigue.
   - `saleRate` = `GetStoredRate(venta)`: `ExchangeRate > 0` y `ExchangeRateTo == baseCurrency`; si no, tipo actual de la divisa; si tampoco hay, `MissingRateSales++` y se omite el registro entero.
   - Para cada compra cerrada: `buyRate` igual (guardado válido, si no actual, si no, omitir la venta como faltante). Si el registro no tiene compras enlazadas (venta anterior a SPEC-02-03), el coste se convierte con el tipo actual como un único bloque `AverageBuyPrice × acciones`, aproximado.
   - Importe = `Amount × saleRate`. Comisión = `saleOp.Commission × saleRate + Σ lot.Commission × buyRate` (si no hay Venta enlazada, `record.Commission × saleRate`). Coste = `Σ lot.PricePerShare × lot.NumberOfShares × buyRate`. Beneficio = importe − coste − comisión.
   - Si algún componente usó el tipo actual: `ApproximateSales++`. Si todo fue guardado: `ConvertedSales++`.
4. Redondeo final a 2 decimales (`MidpointRounding.AwayFromZero`) como hoy.

Los importes convertidos solo alimentan las tarjetas; no se escribe nada.

### 2.4 Página `SalesHistoryList.razor`

- Estado: `SalesPeriodFilter filter = SalesPeriodFilter.All`, `bool hasAnySale`.
- Barra sobre las tarjetas: botones de modo (Día / Mes / Año / Total histórico), control de valor (`input type=date`, `type=month`, número) con `@onchange`, flechas ◀ ▶ y la etiqueta. Estilos con clases Bootstrap/`app.css` existentes; sin CSS nuevo salvo lo imprescindible.
- `LoadRecords` usa `GetByPeriodAsync(filter)` y `HasAnyAsync()`; las acciones (editar precio, deshacer, ingresar) siguen llamando a `LoadRecords`, que conserva el filtro (RF-8).
- Estados: sin ventas en la BD → mensaje actual y sin selector; con ventas pero periodo vacío → selector, tarjetas a 0 y «No hay ventas en este periodo» (RF-7).
- Notas de tarjeta: «Incluye N ventas convertidas a EUR con los tipos guardados de cada compra y venta» y «N ventas usan el tipo actual por no tener tipo guardado» (con `ApproximateSales`); se mantiene la de exclusión.
- Valor inválido o fuera de 2000–2100: `errorMessage` en español, el filtro anterior no cambia.

## 5. Casos límite técnicos

- `SaleDate` tiene hora: rango semiabierto `[desde, hasta)` evita perder ventas del último día.
- Comparación de fechas en SQLite/EF: se pasan `DateTime` sin zona y EF las traduce a texto ISO ordenable; se comprueba en la prueba manual con una venta del 31 y otra del día siguiente.
- `IN` con muchos ids: aceptable para un uso personal; si crece, se trocea.
- Compras cerradas por una venta parcial: la fila cerrada ya tiene `SaleHistoryId` y conserva el tipo del lote.
- `ExchangeRateTo` distinto de la base actual: tipo guardado no válido (aproximada).
- Cambio de modo desde Total histórico: usa hoy; dos clics seguidos en ◀ no pierden la referencia.
